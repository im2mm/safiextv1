Battery Status v1.1.0

Shows the battery status of every BLE temperature/humidity tag on your warehouse objects, in one place, with nested tabs per warehouse.

Why it reads Sensors Tracing: the battery status of a tag arrives as text (BatteryVoltageStatus<tag id>=Normal). Selector sensors fed by a text field show no value in the normal sensor list, so the extension reads the raw packet data (triggerdata) that you also see in Sensors Tracing.

Where to find it

  • Left menu: Battery Status tab, with two inner tabs:
    • Warehouses: region → object tree with a Normal/total badge. Click an object to open it; click a region to filter the overview.
    • Settings: auto refresh and how many hours of Sensors Tracing to read (1 to 24).
  • Main area, three tabs:
    • Overview: summary tiles and every tag grouped by object, with search.
    • Alerts: tags that are not Normal (low battery text, not reporting, unknown text).
    • Warehouses: one vertical tab per object with its tags, the gateway battery and power voltage.

Status rules

  • Normal: text contains normal / ok / good / full.
  • Alert: text contains low, not normal, abnormal, critical, replace, fault and similar words.
  • Not reporting: the tag has a battery sensor but sent no battery value in the selected window.
  • Unknown: any other text, or only a level without text.

Data sources (read-only)

GET ax/tree.php?vehs=1&state=1                    object tree
GET ax/sensors/sensors.php?agent_id=<id>          sensor configuration (cached 30 min)
GET ax/sensors_trace.php?cmd=get&agent_id=<id>
    &ts=<Y-m-dTH:i:s>&te=<Y-m-dTH:i:s>&page=1&start=0&limit=2000

These are legacy PILOT backend endpoints observed in the running web application; they are not part of the documented /api/v3 API. Sensors Tracing accepts one object and at most one day per request, so the extension asks for each tagged object separately, three at a time. Objects without tag fields are skipped after the configuration call. Auto refresh pauses while the browser tab is hidden.
