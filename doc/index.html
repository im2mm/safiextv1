Battery Status v1.2.0

Warehouse Sensor Status inside PILOT: the latest battery voltage of every wireless temperature/humidity sensor on your objects, with the same rules as the Al Safi web report.

Where the values come from: the wireless sensors report inside the raw packet data (triggerdata) that you also see in Sensors Tracing: BatteryVoltage<id>=3.630, BatteryVoltageStatus<id>=Normal, Temperature<id>=5.1, Humidity<id>=60, RSSI<id>=121. <id> is the sensor ID in decimal; the ID printed on the sensor is the same number in hex (2183475330 → 82253082).

Status rules

  • Normal: latest battery voltage is 3.3 V or more.
  • Low: latest battery voltage is below 3.3 V.
  • No reading: no voltage, or the latest voltage is older than 3 hours. It is not counted as Low; the last known voltage is shown greyed out.
  • The platform's own text (BatteryVoltageStatus) is shown under the status when it differs, e.g. "Battery Status: Normal".

Which sensors are listed

  • A sensor is listed when the object's sensor list has a Temperature<id> or Humidity<id> sensor for it. IDs the gateway happens to hear but that are not registered are ignored.
  • The name comes from the Temperature sensor (else Humidity); a BTS-<hex>- prefix is removed ("BTS-82253082-TEMP7" → "TEMP7").
  • Calculated "average" sensors and status/selector sensors are ignored everywhere.

Where to find it

  • Left menu: Battery Status tab, with two inner tabs:
    • Warehouses: site → object tree with a Normal/total badge. Click an object to open it; click a site to filter the overview.
    • Settings: Duration (Now = last 24 hours, or the last 6, 12, 48, 72 hours) and auto refresh (off by default).
  • Main area, three tabs:
    • Overview: tiles Low / No reading / Normal / Sensors-objects (click a tile to filter), every sensor grouped by object (objects with most Low first), filter box, status filter, Fetch battery status, Stop, Download Excel.
    • Alerts: sensors that are Low or No reading.
    • Warehouses: one vertical tab per object with gateway battery, power supply, last packet and an All sensors button.
  • Click any sensor row for its readings in the last 24 hours: count, voltage min/max, readings below 3.3 V, a trend line and the full list.

Excel export

Three sheets: Battery voltage (one row per sensor, Low rows red, No reading rows grey), Gateways (one row per object: IMEI, gateway battery, power supply, last packet, counts, error) and All sensors (every configured sensor with its latest value). The file is saved as .xls; Excel may ask to confirm the format when opening it.

Data sources (read-only)

GET  ax/tree.php?vehs=1&checked=1&node=src           object tree
POST ax/sensors/sensors.php  agent_id=<id>             sensor list (cached 30 min)
GET  ax/sensors_trace.php?cmd=get&agent_id=<id>
     &ts=<dd.mm.yyyy HH:MM>&te=<dd.mm.yyyy HH:MM>
     &page=..&start=..&limit=100&sort=[ts_date DESC]   raw packets

These are legacy PILOT backend endpoints observed in the running web application; they are not part of the documented /api/v3 API. Pages of 100 packets are read newest first until every sensor has a voltage (at most 2000 packets per object; one page for objects without wireless sensors). Three objects are read at a time. The sensor history reads up to 4000 packets of the last 24 hours.
